# Development Setup

This guide will help you set up your development environment for contributing to CyanPrint.

## Prerequisites

Before you begin, ensure you have the following installed:

| Tool | Version | Purpose |
| ---- | ------- | ------- |
| Git | 2.40+ | Version control |
| Docker | 24.0+ | Container runtime for testing |
| Node.js | 20+ | For Argon and Silicon |
| Rust | 1.75+ | For Iridium |
| Go | 1.24+ | For Boron |
| .NET SDK | 8.0+ | For Zinc and Helium C# SDK |
| Python | 3.11+ | For Helium Python SDK |

## Quick Start

### 1. Fork and Clone

```bash
# Fork the repository on GitHub, then clone your fork
git clone https://github.com/YOUR_USERNAME/sulfone.REPO_NAME.git
cd sulfone.REPO_NAME
```

## Repository-Specific Setup

### Iridium (CLI)

```bash
# Additional setup for Iridium
cd sulfone.iridium

# Setup using go-task (Taskfile.yaml)
task setup

# Run CLI in development mode
cargo run -- init test-project
```

### Boron (Executor)

```bash
# Additional setup for Boron
cd sulfone.boron

# Setup using go-task (Taskfile.yaml)
task setup

# Build the project
go build ./...

# Run the executor
go run . --config config/local.yaml
```

### Zinc (Registry API)

```bash
# Additional setup for Zinc
cd sulfone.zinc

# Setup using go-task (Taskfile.yml)
task setup

# Run database migrations using Entity Framework
dotnet ef migrations add InitialCreate --project App

# Start the API server
dotnet run --project App
```

### Argon (Web UI)

```bash
# Additional setup for Argon
cd sulfone.argon

# Create local environment file with required variables
# Required: AUTH_SECRET, DESCOPE_ID, DESCOPE_SECRET, PUBLIC_LANDSCAPE
cp .env .env.local

# Edit .env.local with your settings

# Start development server
bun run dev
```

### Helium (SDKs)

```bash
# Setup for all SDKs
cd sulfone.helium

# TypeScript SDK
cd sdks/node
bun install
bun run build

# Python SDK
cd ../python
poetry install

# .NET SDK
cd ../dotnet
dotnet restore
```

### Silicon (Documentation)

```bash
# Additional setup for Silicon
cd sulfone.silicon

# Install dependencies
bun install

# Start development server
bun run dev

# Build for production
bun run build
```

## Code Style

### Rust Projects

```bash
# Format code
cargo fmt

# Run linter
cargo clippy -- -D warnings
```

### Go Projects

```bash
# Format code
go fmt ./...

# Run linter
golangci-lint run
```

### .NET Projects

```bash
# Format code
dotnet format

# Build with warnings as errors
dotnet build /warnaserror
```

### TypeScript Projects

```bash
# Format and lint
bun run lint:fix
# or
biome lint --write .
```

### Python Projects

```bash
# Format with black
black src/

# Sort imports
isort src/

# Lint with ruff
ruff check src/
```

## Testing

### Unit Tests

Each repository has its own test command:

| Repository | Command |
| ---------- | ------- |
| Iridium | `cargo test` |
| Boron | `go test ./...` |
| Zinc | `dotnet test` |
| Argon | `bun run test` |
| Helium (TS) | `bun run test` |
| Helium (Python) | `poetry run python template_test.py` |
| Helium (.NET) | `dotnet test` |
| Silicon | N/A (no tests configured) |

### Integration Tests

Some repositories have integration tests that require Docker:

<Tabs groupId="repo" items={['Rust (Iridium)', 'Go (Boron)', '.NET (Zinc)']} persist>
<Tab value="Rust (Iridium)">

```bash
# Start test infrastructure
docker-compose -f docker-compose.test.yml up -d

# Run integration tests
cargo test --features integration

# Cleanup
docker-compose -f docker-compose.test.yml down
```

</Tab>
<Tab value="Go (Boron)">

```bash

docker-compose -f docker-compose.test.yml up -d

# Run integration tests
go test -tags=integration ./...

# Cleanup
docker-compose -f docker-compose.test.yml down
```

</Tab>

```bash

docker-compose -f docker-compose.test.yml up -d

# Run integration tests
dotnet test --filter "Category=Integration"

docker-compose -f docker-compose.test.yml down
```

## Troubleshooting

### Common Issues

**Docker not running:**
```bash
# Start Docker Desktop or Docker daemon
# Linux: sudo systemctl start docker
```

**Port already in use:**
```bash
# Find process using port
lsof -i :8080
# Kill process
kill -9 <PID>
```

**Database connection errors:**
```bash
# Check if PostgreSQL is running
docker ps | grep postgres
# Restart if needed
docker-compose restart postgres
```
