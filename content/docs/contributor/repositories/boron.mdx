# sulfone.boron

Boron is the execution coordinator that manages container-based template execution. It handles container lifecycle, template warming, processor/plugin execution, and file operations.

## Repository

[github.com/AtomiCloud/sulfone.boron](https://github.com/AtomiCloud/sulfone.boron)

## Tech Stack

| Technology | Purpose |
| ---------- | ------- |
| Go 1.24 | Primary language |
| Gin | HTTP/REST framework |
| urfave/cli | CLI framework |
| Docker | Container management |
| google/uuid | UUID generation |

## API

Boron exposes a REST HTTP API on port 9000:

| Method | Endpoint | Description |
| ------ | -------- | ----------- |
| GET | `/` | Health check |
| POST | `/executor` | Start a new execution session |
| DELETE | `/executor/:sessionId` | Stop and remove execution session |
| POST | `/executor/:sessionId` | Execute in existing session |
| POST | `/executor/:sessionId/warm` | Warm executor for session |
| POST | `/template/warm` | Warm template containers |
| POST | `/merge/:sessionId` | Merge execution results |
| POST | `/zip` | Create ZIP archive |
| POST | `/proxy/template/:cyanId/api/template/init` | Proxy template initialization |
| POST | `/proxy/template/:cyanId/api/template/validate` | Proxy template validation |

## Resource Management

Boron uses CPU-based parallelism for execution:

```go
// Parallelism is based on available CPUs
cpu := runtime.NumCPU()
```

Execution is managed through a `ParallelismLimit` mechanism rather than explicit resource limits per container.

## Building

```bash
# Build
go build

# Run tests
go test ./...

# Run locally (requires Docker)
go run . --registry <registry-endpoint>
```

## Configuration

Boron uses CLI flags for configuration:

```bash
boron --registry <zinc-registry-endpoint>
```

The `--registry` flag specifies the Zinc registry endpoint for container image resolution.

## Container Types

Boron manages several container types:

| Type | Purpose |
| ---- | ------- |
| Template | Main template execution |
| Processor | Post-processing operations |
| Plugin | Plugin extensions |
| Merger | Result merging operations |

## Volume Management

Boron manages Docker volumes for workspace isolation between execution sessions using a `DockerVolumeReference` system.

## Contributing

When contributing to Boron:

1. Follow Go best practices for goroutine handling
2. Test container isolation thoroughly using the Gin framework
3. Handle resource cleanup in error paths
4. Add appropriate logging for new features
5. Document API changes in the REST endpoint definitions
