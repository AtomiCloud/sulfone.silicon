# sulfone.iridium

The CyanPrint command-line interface (CLI) is the primary way users interact with CyanPrint. It handles project creation, template management, and configuration.

## Repository

[github.com/AtomiCloud/sulfone.iridium](https://github.com/AtomiCloud/sulfone.iridium)

## Workspace Structure

Iridium is a Rust workspace containing 4 crates:

| Crate | Purpose |
| ----- | ------- |
| cyanprint | Main CLI binary with commands |
| cyanprompt | Interactive prompt handling |
| cyanregistry | Registry client for Zinc API |
| cyancoordinator | Coordinator client for Boron communication |

## Tech Stack

| Technology | Purpose |
| ---------- | ------- |
| Rust | Primary language for performance and safety |
| Clap | CLI argument parsing framework |
| Tokio | Async runtime |
| Reqwest | HTTP client for API calls |
| Bollard | Docker client for container management |
| Inquire | Interactive CLI prompts |

## Commands

The CLI provides the following main commands:

```bash
# Create a new project from a template
cyanprint create <template-ref> [path]

# Create with custom coordinator endpoint
cyanprint create <template-ref> --coordinator-endpoint <url>

# Update an existing project
cyanprint update [path]

# Update interactively (select specific versions)
cyanprint update --interactive

# Push artifacts to the registry
cyanprint push template <path>
cyanprint push group <path>
cyanprint push plugin <path>
cyanprint push processor <path>

# Run the daemon locally
cyanprint daemon

# Enable debug output (available on all commands)
cyanprint -d create <template-ref>
cyanprint --debug update
```

## Building

```bash
# Debug build
cargo build

# Release build
cargo build --release

# Run tests
cargo test

# Run with logging
RUST_LOG=debug cargo run -- create <template-ref>
```

## Configuration

Iridium is configured via environment variables and command-line flags:

| Environment Variable | Description | Default |
| ------------------- | ----------- | ------- |
| `CYANPRINT_REGISTRY` | Zinc registry URL | `https://api.zinc.sulfone.raichu.cluster.atomi.cloud` |
| `CYANPRINT_COORDINATOR` | Coordinator endpoint | `http://coord.cyanprint.dev:9000` |
| `CYAN_TOKEN` | Authentication token | (none) |

Example usage:

```bash
# Set custom registry
export CYANPRINT_REGISTRY=https://custom-registry.example.com

# Set authentication token
export CYAN_TOKEN=your-auth-token

# Use custom coordinator for create command
cyanprint create <template-ref> --coordinator-endpoint http://localhost:9000
```
