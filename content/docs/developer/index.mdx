# Developer Documentation

Welcome to the CyanPrint developer documentation. This section guides you through creating reusable artifacts that power the CyanPrint ecosystem.

## Three Types of Artifacts

CyanPrint provides three extensibility points for developers:

### Templates

Templates are the primary artifact type. They define file structures, content patterns, and user interactions for generating projects. Templates use glob patterns to select files and processors to transform content.

### Processors

Processors transform file content during template execution. The default processor uses Eta templating, but you can create custom processors for specialized transformations like code generation, configuration merging, or format conversion.

## Multi-Language SDK Support

The Helium SDK is available in three languages, allowing you to write artifacts in your preferred language:

import { Tab, Tabs } from 'fumadocs-ui/components/tabs';

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```bash
npm install @atomicloud/helium-sdk
```

  </Tab>
  <Tab value=".NET">

```bash
dotnet add package AtomiCloud.Helium
```

  </Tab>
  <Tab value="Python">

```bash
pip install cyanprint-helium
```

  </Tab>
</Tabs>

All SDKs provide equivalent functionality with idiomatic APIs for each language. Code examples throughout this documentation show implementations in all three languages.
