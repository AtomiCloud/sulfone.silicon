# Glob and Copy

This tutorial teaches you the fundamentals of template creation using glob patterns and file copying. You'll build a simple template that copies files without any content transformation.

**Time estimate**: 10-15 minutes

## What is a Template?

A CyanPrint template is a blueprint for generating project files. At its simplest, a template:

1. **Selects files** using glob patterns
2. **Copies files** to the output directory
3. **Optionally transforms** file content using processors

In this tutorial, we'll focus on the first two steps.

Before starting, ensure you have:

- CyanPrint CLI installed
- Basic familiarity with your chosen SDK language

## Create the Template Entry Point

### Implement ICyanTemplate

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

Create `template/index.ts`:

```ts
import { Cyan, ICyanTemplate } from '@atomicloud/helium-sdk';

export default class SimpleTemplate implements ICyanTemplate {
  async execute(cyan: Cyan): Promise<void> {
    // Define files to copy using glob patterns
    const files = cyan.glob('template/files/**/*');

    // Copy all matched files to output
    for (const file of files) {
      await cyan.files.copy(
        file,
        file.replace('template/files/', '')
      );
    }
  }
}
```

  <Tab value=".NET">

Create `Template.cs`:

using AtomiCloud.Helium;

public class SimpleTemplate : ICyanTemplate

## Understanding Glob Patterns

Glob patterns define which files to select. Here are the most common patterns:

| Pattern | What it matches |
| ------- | --------------- |
| `*` | Any single file in current directory |
| `**` | Any directory depth |
| `**/*` | All files recursively |
| `**/*.ts` | All TypeScript files |
| `src/**/*` | All files under `src/` |
| `!node_modules/**` | Exclude `node_modules` |

### Common Glob Examples

```bash
# Match all TypeScript files
**/*.ts

# Match all files in src, excluding tests
src/**/*
!src/**/*.test.ts

# Match specific file types
**/*.{ts,tsx,js,jsx}

# Exclude common directories
**/*
!node_modules/**
!.git/**
!dist/**
```

### Multiple Patterns

## Configure the Template

Create `cyanprint.json` in the root directory:

```json
{
  "name": "my-first-template",
  "version": "1.0.0",
  "description": "A simple template demonstrating glob and copy",
  "author": "Your Name",
  "license": "MIT",
  "processors": [],
  "plugins": []
}
```

<Callout type="info">
Since we're only copying files without transformation, we don't need any processors yet. In the next tutorial, you'll add the default processor for templating.
</Callout>

## Project Structure

Your project should now look like this:

```
my-first-template/
├── cyanprint.json
├── package.json          # or .csproj / requirements.txt
├── template/
│   ├── index.ts          # Entry point
│   └── files/            # Files to copy
│       ├── README.md
│       ├── package.json
│       └── src/
│           └── index.ts
└── node_modules/         # or equivalent
```

## Test the Template

### Local Testing

Test your template locally before publishing:

```bash
# Create a test output directory
mkdir test-output

# Run the template
cyanprint init test-output --local .
```

The CLI will:
1. Load your local template
2. Execute the template code
3. Copy files to `test-output/`

### Verify Output

Check the generated files:

```bash
ls test-output/
# Should show: README.md  package.json  src/

ls test-output/src/
# Should show: index.ts
```
