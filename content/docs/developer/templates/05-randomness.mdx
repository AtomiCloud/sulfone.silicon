# Working with Randomness

Templates sometimes need random values—unique IDs, random ports, or shuffled lists. CyanPrint's determinism system ensures these values are reproducible across executions.

## Why Determinism Matters

<Callout type="info">
When you run a template twice with the same inputs, you should get identical outputs. Deterministic random generation ensures this consistency, which is essential for:
</Callout>

- **Reproducible builds** - Same inputs produce same outputs
- **Version control** - Generated files can be tracked
- **Testing** - Predictable results in test environments
- **Auditing** - Traceable generation process

## UUID Generation

Generate unique identifiers that are deterministic based on the seed.

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```ts
// Generate a single UUID
const id = cyan.determinism.uuid();
// Returns: 'a1b2c3d4-e5f6-7890-abcd-ef1234567890'

// Generate multiple UUIDs (each call produces a different value)
const userId = cyan.determinism.uuid();
const sessionId = cyan.determinism.uuid();
const requestId = cyan.determinism.uuid();
```

  </Tab>

<Callout type="tip">
Each UUID call advances the internal state, so subsequent calls return different values. The sequence is deterministic based on the initial seed.
</Callout>

## Shuffling Arrays

Shuffle arrays in a deterministic order.

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```ts
// Shuffle an array
const colors = ['red', 'blue', 'green', 'yellow'];
const shuffled = cyan.determinism.shuffle(colors);

// Use for random order in templates
const features = ['auth', 'logging', 'caching', 'metrics'];
const implementationOrder = cyan.determinism.shuffle(features);

// The original array is not modified
console.log(colors); // ['red', 'blue', 'green', 'yellow']
console.log(shuffled); // ['green', 'red', 'yellow', 'blue'] (example)
```

  </Tab>
  <Tab value=".NET">


## Practical Example: Development Environment

Here's a complete example using determinism to generate a development environment configuration:

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```ts
import { Cyan, ICyanTemplate } from '@atomicloud/helium-sdk';

export default class DevEnvTemplate implements ICyanTemplate {
  async execute(cyan: Cyan): Promise<void> {
    // Generate deterministic configuration
    const config = {
      app: {
        id: cyan.determinism.uuid(),
        port: cyan.determinism.randomInt(3000, 9999),
        secret: cyan.determinism.randomString(32)
      },
      database: {
        port: cyan.determinism.randomInt(5432, 6432),
        password: cyan.determinism.randomString(16)
      },
      redis: {
        port: cyan.determinism.randomInt(6379, 7379)
      },
      services: {
        order: cyan.determinism.shuffle(['api', 'worker', 'scheduler'])
      }
    };

    // Store in answers for use in templates
    cyan.answers.config = config;

    // Process configuration file
    await cyan.processors.run('default-processor', {
      input: 'templates/docker-compose.yml',
      output: 'docker-compose.yml'
    });
  }
}
```

## Seed Behavior

The determinism seed is derived from:

1. User answers (if provided)
2. Template version
3. Execution context

This means:
- Same answers + same version = same output
- Different answers = different output
- Version change = different output (expected for upgrades)

<Callout type="warn">
Never use JavaScript's `Math.random()`, Python's `random` module, or .NET's `Random` class directly. These produce non-deterministic results across different execution environments. Always use `cyan.determinism` instead.
</Callout>
