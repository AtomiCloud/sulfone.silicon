# Shared Answers

When using multiple templates together, you often want to share answers between them. This guide shows you how to make templates share common configuration without re-prompting users.

## Why Share Answers?

In composite templates or template chains:

- **Avoid repetition** - Don't ask for the project name multiple times
- **Ensure consistency** - Same value used across all templates
- **Improve UX** - Faster template execution

## Answer Namespacing

CyanPrint uses namespaces to organize answers and prevent conflicts:

import { Tab, Tabs } from 'fumadocs-ui/components/tabs';

```
cyan.answers
├── projectName      # Global/shared
├── author          # Global/shared
├── template1       # Template-specific
│   ├── feature1
│   └── feature2
└── template2       # Template-specific
    └── feature3
```

## Defining Shared Answers

### In cyanprint.json

```json
{
  "name": "my-template",
  "version": "1.0.0",
  "sharedAnswers": ["projectName", "author", "license"],
  "processors": [...]
}
```

Answers defined in `sharedAnswers` are:
1. **Checked first** - If already provided by parent template, use existing value
2. **Stored globally** - Available to child templates
3. **Prompted once** - Only ask if not already available

## Using Shared Answers

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```ts
import { Cyan, ICyanTemplate } from '@atomicloud/helium-sdk';

export default class SharedTemplate implements ICyanTemplate {
  async execute(cyan: Cyan): Promise<void> {
    // Check if answer already exists
    if (!cyan.answers.projectName) {
      // Only prompt if not already provided
      cyan.answers.projectName = await cyan.inquirer.text({
        message: 'Project name:'
      });
    }

    // Use the answer (either from shared or just prompted)
    const projectName = cyan.answers.projectName;

    // Process files with the shared answer
    await cyan.processors.run('default-processor', {
      input: 'template/package.json',
      output: 'package.json'
    });
  }
}
```

## Answer Helpers

The SDK provides helpers for conditional prompting:

```ts
// Helper: getOrPrompt
const projectName = await cyan.answers.getOrPrompt('projectName', {
  message: 'Project name:',
  default: 'my-project'
});

// Helper: getOrPrompt with validation
const email = await cyan.answers.getOrPrompt('email', {
  message: 'Email:',
  validate: (value) => value.includes('@') || 'Invalid email'
});

// Helper: getOrPromptSelect
const framework = await cyan.answers.getOrPromptSelect('framework', {
  message: 'Framework:',
  options: ['React', 'Vue', 'Svelte']
});

const features = await cyan.answers.getOrPromptCheckbox('features', {
```

## Template Composition Pattern

When composing multiple templates, define shared answers at the parent level:

```json
// parent-template/cyanprint.json
{
  "name": "fullstack-app",
  "version": "1.0.0",
  "sharedAnswers": [
    "projectName",
    "author",
    "license",
    "database"
  ],
  "children": [
    {
      "name": "frontend",
      "template": "@company/react-template"
    },
    {
      "name": "backend",
      "template": "@company/api-template"
    }
  ]
}
```

### Parent Template

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```ts
import { Cyan, ICyanTemplate } from '@atomicloud/helium-sdk';

export default class FullstackTemplate implements ICyanTemplate {
  async execute(cyan: Cyan): Promise<void> {
    // Collect shared answers first
    await this.collectSharedAnswers(cyan);

    // Execute child templates
    await cyan.children.run('frontend');
    await cyan.children.run('backend');
  }

  private async collectSharedAnswers(cyan: Cyan): Promise<void> {
    cyan.answers.projectName = await cyan.answers.getOrPrompt('projectName', {
      message: 'Project name:'
    });

    cyan.answers.author = await cyan.answers.getOrPrompt('author', {
      message: 'Author:'
    });

    cyan.answers.database = await cyan.answers.getOrPromptSelect('database', {
      message: 'Database:',
      options: ['PostgreSQL', 'MySQL', 'MongoDB']
    });
  }
}
```

```python
class FullstackTemplate(ICyanTemplate):

        await self._collect_shared_answers(cyan)

    async def _collect_shared_answers(self, cyan: Cyan):
```

### Child Templates

Child templates can rely on shared answers being available:

```ts
// frontend template
export default class FrontendTemplate implements ICyanTemplate {
  async execute(cyan: Cyan): Promise<void> {
    // projectName is already set by parent

    const framework = await cyan.inquirer.select({
      message: 'Frontend framework:',
      options: ['React', 'Vue', 'Svelte']
    });

    // Process files
    await cyan.processors.run('default-processor', {
      input: 'template/**/*',
      output: '.'

}
```

## Answer Scope

| Scope | Description | Access |
| ----- | ----------- | ------ |
| Global | Available to all templates | `cyan.answers.key` |
| Template-local | Specific to current template | `cyan.answers.templateName.key` |
| Private | Not shared with children | `cyan.answers._private.key` |

## Best Practices

1. **Declare shared answers** in `cyanprint.json` for documentation
2. **Use helper methods** to avoid manual existence checks
3. **Namespace specific answers** to avoid conflicts
4. **Document expected shared answers** in your template README
