# Plugins in Templates

Plugins provide reusable functionality that templates can leverage. This guide shows you how to use plugins in your templates.

## What are Plugins?

Plugins are CyanPrint artifacts that:

- Add helper functions and utilities
- Provide integrations with external services
- Hook into template lifecycle events
- Share common functionality across templates

Unlike templates (which generate files) and processors (which transform content), plugins provide **behavioral extensions**.

## Declaring Plugin Dependencies

In `cyanprint.json`:

```json
{
  "name": "my-template",
  "version": "1.0.0",
  "plugins": [
    {
      "name": "git-plugin",
      "version": "^1.0.0"
    },
    {
      "name": "license-plugin",
      "version": "^2.0.0"
    }
  ]
}
```

import { Cyan, ICyanTemplate } from '@atomicloud/helium-sdk';

export default class MyTemplate implements ICyanTemplate {
  async execute(cyan: Cyan): Promise<void> {
    // Collect answers
    const projectName = await cyan.inquirer.text({
      message: 'Project name:'
    });

    // Use git plugin to initialize repository
    const gitPlugin = cyan.plugins.get('git-plugin');
    await gitPlugin.init({
      name: projectName,
      branch: 'main'
    });

    // Use license plugin to generate LICENSE file
    const licensePlugin = cyan.plugins.get('license-plugin');
    const licenseContent = await licensePlugin.generate({
      type: 'MIT',
      year: new Date().getFullYear(),
      holder: cyan.answers.author
    });

    await cyan.files.write('LICENSE', licenseContent);
  }
}

## Common Plugin Types

### Git Plugin

Initialize and configure Git repositories:

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```ts
const git = cyan.plugins.get('git-plugin');

// Initialize repository
await git.init({ branch: 'main' });

// Add files
await git.add('.');

// Create initial commit
await git.commit('Initial commit from template');

// Add remote
await git.addRemote('origin', 'https://github.com/user/repo.git');
```

### Validator Plugin

Validate user input:

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```ts
const validator = cyan.plugins.get('validator-plugin');

// Validate project name
const projectName = await cyan.inquirer.text({
  message: 'Project name:',
  validate: async (value) => {
    if (!validator.isPackageName(value)) {
      return 'Must be a valid package name (lowercase, alphanumeric, dashes)';
    }
    if (await validator.isPackageTaken(value)) {
      return 'Package name is already taken on npm';
    }
    return true;
  }
});

// Validate GitHub repository
const repo = await cyan.inquirer.text({
  message: 'GitHub repository:',
  validate: (value) => {
    if (!validator.isGitHubRepo(value)) {
      return 'Must be in format: owner/repo';
    }
    return true;
  }
});
```

  </Tab>
  <Tab value=".NET">

    if not validator.is_package_name(value):
        return "Must be a valid package name (lowercase, alphanumeric, dashes)"
    if await validator.is_package_taken(value):

## Plugin Lifecycle Hooks

Plugins can hook into template lifecycle events:

```json
{
  "plugins": [
    {
      "name": "audit-plugin",
      "hooks": {
        "beforeExecute": true,
        "afterExecute": true,
        "onError": true
      }
    }
  ]
}
```

### Available Hooks

| Hook | When it runs |
| ---- | ------------ |
| `beforeExecute` | Before template execution starts |
| `afterInquirer` | After user questions are answered |
| `beforeProcess` | Before file processing begins |
| `afterProcess` | After file processing completes |
| `afterExecute` | After template execution finishes |
| `onError` | When an error occurs |

## Best Practices

1. **Check plugin availability** before using
2. **Handle missing plugins** gracefully
3. **Document required plugins** in README
4. **Version pin** for stability
