# Testing Templates

Testing ensures your templates work correctly before publishing. This guide covers local testing strategies and best practices.

## Why Test Templates?

- **Catch errors early** - Identify issues before users encounter them
- **Ensure reproducibility** - Verify consistent output
- **Validate interactions** - Test question flows
- **Document behavior** - Tests serve as documentation

## Local Testing

### Basic Test Run

Test your template locally using the `--local` flag:

```bash
# Test from template directory
cyanprint init test-output --local .

# Test with specific version
cyanprint init test-output --local . --version 1.0.0
```

### Test Directory Structure

```
my-template/
├── template/
│   ├── index.ts
│   └── files/
├── tests/
│   ├── basic.test.ts
│   ├── features.test.ts
│   └── fixtures/
│       └── expected-output/
├── cyanprint.json
└── package.json
```

```ts
// tests/template.test.ts
import { describe, it, expect } from 'vitest';
import { TemplateTester } from '@atomicloud/helium-testing';
import path from 'path';

describe('My Template', () => {
  const tester = new TemplateTester({
    templatePath: path.join(__dirname, '..')
  });

  it('generates basic project structure', async () => {
    const result = await tester.run({
      answers: {
        projectName: 'test-project',
        description: 'A test project'
      }
    });

    expect(result.success).toBe(true);
    expect(result.files).toContain('package.json');
    expect(result.files).toContain('README.md');
    expect(result.files).toContain('src/index.ts');
  });

  it('includes TypeScript files when selected', async () => {
    const result = await tester.run({
      answers: {
        projectName: 'ts-project',
        typescript: true
      }
    });

    expect(result.files).toContain('tsconfig.json');
    expect(result.files).toContain('src/index.ts');
  });

  it('excludes TypeScript files when not selected', async () => {
    const result = await tester.run({
      answers: {
        projectName: 'js-project',
        typescript: false
      }
    });

    expect(result.files).not.toContain('tsconfig.json');
  });
});
```

```ts
  it('matches snapshot for default options', async () => {

    // Create snapshot of file structure
```

## Testing Interactions

Test question flows and validations:

<Tabs groupId="sdk-language" items={['TypeScript', '.NET', 'Python']} persist>
  <Tab value="TypeScript">

```ts
describe('Interactions', () => {
  it('validates project name', async () => {
    const result = await tester.run({
      answers: {
        projectName: 'Invalid Name!'  // Should fail validation
      },
      validateOnly: true
    });

    expect(result.valid).toBe(false);
    expect(result.errors).toHaveProperty('projectName');
  });

  it('accepts valid project name', async () => {
    const result = await tester.run({
      answers: {
        projectName: 'valid-project-name'
      },
      validateOnly: true
    });

    expect(result.valid).toBe(true);
  });

  it('handles all feature combinations', async () => {
    const featureCombos = [
      ['typescript'],
      ['typescript', 'eslint'],
      ['typescript', 'eslint', 'testing'],
      ['eslint', 'testing'],
      []
    ];

    for (const features of featureCombos) {
      const result = await tester.run({
        answers: {
          projectName: 'test',
          features
        }
      });

      expect(result.success).toBe(true);
    }
  });
});
```

## CI Integration

Add testing to your CI pipeline:

```yaml
# .github/workflows/test.yml
name: Test Template

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

      - name: Upload coverage
        uses: codecov/codecov-action@v3
```

## Best Practices

1. **Test all question paths** - Every branch in your inquirer flow
2. **Test edge cases** - Empty strings, special characters, max lengths
3. **Test determinism** - Verify same inputs produce same outputs
4. **Use descriptive names** - Tests document behavior
5. **Keep tests fast** - Use mocks for external dependencies
