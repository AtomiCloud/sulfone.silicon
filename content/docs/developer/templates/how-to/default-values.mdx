# How to Set Default Values

Default values improve user experience by providing sensible starting points.

## Shorthand vs Object Form

Shorthand forms don't support defaults. Use the object form for default values:

```ts
// Shorthand - no default support
const name = await i.text('Name?', 'project.name', 'Enter name');

// Object form - supports default
const name = await i.text({
  type: QuestionType.Text,
  id: 'project.name',
  message: 'Name?',
  desc: 'Enter project name',
  default: 'my-project'  // Default value
});
```

## Default by Question Type

### Text

The `text()` question type supports two ways to set initial values:

- `default`: A fallback value used when no user input is provided
- `initial`: A pre-filled value that appears in the input field (user can edit)

```ts
const name = await i.text({
  type: QuestionType.Text,
  id: 'project.name',
  message: 'Project name?',
  desc: 'Enter name',
  default: 'my-project'  // Fallback if user provides no input
});
```

Using `initial` for pre-filled input:

```ts
const name = await i.text({
  type: QuestionType.Text,
  id: 'project.name',
  message: 'Project name?',
  desc: 'Enter name',
  initial: 'my-project'  // Pre-filled in input field, user can edit
});
```

### Confirm

```ts
const typescript = await i.confirm({
  type: QuestionType.Confirm,
  id: 'project.typescript',
  message: 'Use TypeScript?',
  desc: 'Add TypeScript config',
  default: true  // true or false
});
```

### Date

The `dateSelect()` method accepts a `Date` object for the `default` property, but returns the selected date as a **string** (ISO format):

```ts
const startDate = await i.dateSelect({
  type: QuestionType.DateSelect,
  id: 'project.start',
  message: 'Start date?',
  desc: 'Project start',
  default: new Date()  // Date object as input
});
// startDate is a string, e.g., "2024-01-15"
```

:::caution
`select()` and `checkbox()` question types do **not** support the `default` property. Users must make an active selection for these question types.
:::

## Computed Defaults

Calculate defaults dynamically:

```ts
const projectName = await i.text({
  type: QuestionType.Text,
  id: 'project.name',
  message: 'Project name?',
  desc: 'Enter name',
  default: process.cwd().split('/').pop() || 'my-project'  // Current directory name
});
```

```ts
// Default to one month from now
const defaultDeadline = new Date();
defaultDeadline.setMonth(defaultDeadline.getMonth() + 1);

const deadline = await i.dateSelect({
  type: QuestionType.DateSelect,
  id: 'project.deadline',
  message: 'Deadline?',
  desc: 'Target date',
  default: defaultDeadline
});
// deadline is returned as a string (ISO format)
```

## Conditional Defaults

Set defaults based on previous answers. Note that `confirm()` and `text()` support defaults, but `select()` and `checkbox()` do not:

```ts
const typescript = await i.confirm({
  type: QuestionType.Confirm,
  id: 'project.typescript',
  message: 'Use TypeScript?',
  desc: 'Add TypeScript config',
  default: true
});

// Conditional default for a text question based on previous answer
const configExt = await i.text({
  type: QuestionType.Text,
  id: 'project.configExt',
  message: 'Config file extension?',
  desc: 'Enter extension',
  default: typescript ? '.ts' : '.js'  // Conditional default
});
```

For `select()` and `checkbox()` questions, users must make an active selection since these types do not support defaults:

```ts
const framework = await i.select({
  type: QuestionType.Select,
  id: 'project.framework',
  message: 'Framework?',
  desc: 'Choose framework',
  options: ['React', 'Vue', 'Svelte']
  // Note: No default - user must select
});

// Based on framework choice, suggest but don't pre-select testing tool
const testFramework = await i.select({
  type: QuestionType.Select,
  id: 'project.testing',
  message: 'Test framework?',
  desc: 'Choose testing tool',
  options: framework === 'Vue' ? ['Vitest', 'Jest', 'Mocha'] : ['Jest', 'Vitest', 'Mocha']
  // Note: No default - user must select
});
```

## Best Practices

1. **Be opinionated** - Provide sensible defaults for common choices
2. **Document defaults** - Make it clear what the default is
3. **Consider context** - Defaults should match the project type
4. **Allow override** - Users should always be able to change the default
5. **Know the limits** - Only `text()`, `confirm()`, and `dateSelect()` support defaults; `select()` and `checkbox()` do not
