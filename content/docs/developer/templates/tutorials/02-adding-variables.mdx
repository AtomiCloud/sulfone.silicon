# Tutorial 2: Adding Variables

Add variable substitution using the default processor. This enables dynamic content generation based on variables.

## Change to GlobType.Template

First, update your file configuration to use `GlobType.Template` instead of `GlobType.Copy`:

```ts -c
files: [{ root: 'template', glob: '**/*', exclude: [], type: GlobType.Template }]
```

<Callout type="warn">
Using `GlobType.Template` on binary files (images, PDFs) will corrupt them. See [Tutorial 3](/docs/developer/templates/tutorials/03-changing-glob) for handling mixed file types.
</Callout>

## Add Variables to Config

Define variables in your processor configuration:

```ts -c
config: {
  vars: {
    name: 'my-project',
    author: 'Your Name',
    version: '1.0.0'
  }
}
```

## Use Variables in Files

The default processor uses `var__name__` syntax for variable substitution:

`cyan/template/README.md`:

```markdown template/README.md
# var__name__

Welcome to var__name__!

**Author:** var__author__
**Version:** var__version__
```

## Complete Example

Update `cyan/index.ts`:

```ts cyan/index.ts -c
import { StartTemplateWithLambda, GlobType } from '@atomicloud/cyan-sdk';

StartTemplateWithLambda(async (i, d) => {
  return {
    processors: [{
      name: 'cyan/default',
      files: [
        { root: 'template', glob: '**/*', exclude: [], type: GlobType.Template }
      ],
      config: {
        vars: {
          name: 'my-project',
          author: 'Your Name',
          version: '1.0.0'
        }
      }
    }]
  };
});
```

## Variable Syntax

The default processor uses Eta templating with custom delimiters:

| Syntax | Description |
|--------|-------------|
| `var__name__` | Variable substitution |
| `var__user.name__` | Nested variable access |

<Callout type="info">
The default delimiter `var__` and `__` is chosen to avoid conflicts with common template syntaxes like `${}` or `{{}}`.
</Callout>
