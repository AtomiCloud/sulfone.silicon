# Your First Template

This tutorial walks you through the complete process of creating a project from a CyanPrint template. We'll use a realistic example to demonstrate all the steps involved.

**Time estimate**: 10-15 minutes

## What You'll Build

In this tutorial, you'll create a full-stack web application using a template from the CyanPrint registry. By the end, you'll understand:

- How to browse and evaluate templates
- How to run a template with various options
- How to respond to template prompts
- What the generated project structure looks like

## Prerequisites

Make sure you've completed [Getting Started](./01-getting-started) or have:

- CyanPrint CLI installed and working
- Docker running on your system
- Basic familiarity with command-line operations

## Step 1: Browse the Registry

Before running a template, it's helpful to explore what's available. You have two options:

### Option A: Web Registry

Visit the CyanPrint web registry (Argon) to browse templates visually. This is useful for:

- Seeing template screenshots and previews
- Reading detailed documentation
- Checking version history and update notes
- Viewing usage statistics and ratings

### Option B: CLI Search

Use the CLI for quick searches:

```bash
# Search for web templates
cyanprint search web

# Filter by framework
cyanprint search --tag nextjs
cyanprint search --tag express

# Filter by language
cyanprint search --language typescript
```

<Callout type="tip">
Combine the web registry for discovery with the CLI for execution. The web interface is great for exploring, while the CLI provides a streamlined workflow for running templates.
</Callout>

## Step 2: Choose a Template

For this tutorial, let's use the `nextjs-dashboard` template, which creates a modern dashboard application with:

- Next.js 14 with App Router
- TypeScript configuration
- Tailwind CSS for styling
- Authentication scaffolding
- Database setup with Prisma

```bash
# View template details
cyanprint show nextjs-dashboard
```

## Step 3: Initialize the Project

Now let's create a project using this template:

```bash
cyanprint init my-dashboard --template nextjs-dashboard
```

<Callout type="info">
If you don't specify a template, the CLI will prompt you to select one interactively. You can also use `-t` as shorthand for `--template`.
</Callout>

The CLI will:

1. **Download** the template package from the registry
2. **Validate** the template signature and checksum
3. **Prepare** an isolated Docker container
4. **Execute** the template logic


<Callout type="warn">
Take your time with these choices! Some options (like the database) are harder to change later. When in doubt, accept the defaults which represent recommended best practices.
</Callout>

4. **`prisma/schema.prisma`** - Database schema tailored to your database choice

## Step 7: Get Started

Follow the generated README to start developing:

```bash
# Install dependencies
npm install

# Copy environment file
cp .env.example .env

# Set up the database
npx prisma db push

# Start development server
npm run dev
```

Visit `http://localhost:3000` to see your new application!

## What's Happening Behind the Scenes

When you run `cyanprint init`, several things happen:

1. **Template Resolution**: The CLI fetches template metadata from the registry
2. **Container Creation**: A Docker container is spun up with the template's runtime
3. **Input Processing**: Your answers are passed to the template engine
4. **File Generation**: The template logic creates and configures files
5. **Output Transfer**: Generated files are copied to your local directory

For a deeper dive, see [Template Lifecycle](./08-template-lifecycle).
