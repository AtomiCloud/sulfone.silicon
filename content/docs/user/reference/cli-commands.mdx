# CLI Commands Reference

## Global Options

| Flag                   | Default                                                    | Description              |
| ---------------------- | ---------------------------------------------------------- | ------------------------ |
| `-r, --registry <URL>` | `https://api.zinc.sulfone.raichu.cluster.atomi.cloud`      | Registry endpoint        |
| `-d, --debug`          | —                                                          | Enable debug output      |
| `--version`            | —                                                          | Print version            |

### Environment Variables

| Variable              | Corresponding Flag        |
| --------------------- | ------------------------- |
| `CYANPRINT_REGISTRY`  | `-r, --registry`          |

### Command Aliases

| Command      | Alias |
| ------------ | ----- |
| `create`     | `c`   |

| `push`       | `p`   |

## `cyanprint create`

Create a new project from a template.

```bash -c
cyanprint create <TEMPLATE_REF> [PATH]
```

### Arguments

| Argument         | Required | Description                                                   |
| ---------------- | -------- | ------------------------------------------------------------- |
| `<TEMPLATE_REF>` | Yes      | Template reference (format: `<username>/<name>:<version>`)    |
| `[PATH]`         | No       | Output directory (default: .)                                 |

### Options

| Option                       | Default                                                    | Description     |
| ---------------------------- | ---------------------------------------------------------- | --------------- |
| `-c, --coordinator-endpoint` | `http://coord.cyanprint.dev:9000`                          | Coordinator URL |

### Environment Variables

| Variable               | Corresponding Flag           |
| ---------------------- | ---------------------------- |
| `CYANPRINT_COORDINATOR`| `-c, --coordinator-endpoint` |

## `cyanprint update`

Update an existing project to the latest template version. This command uses the `.cyan_state.yaml` file to perform a 3-way merge between your local changes and the upstream template.

```bash -c
cyanprint update [PATH]
```

### Options

| Option                       | Description                   |
| ---------------------------- | ----------------------------- |
| `-i, --interactive`          | Select versions interactively |
| `-c, --coordinator-endpoint` | Coordinator URL               |

### Environment Variables

| Variable               | Corresponding Flag           |
| ---------------------- | ---------------------------- |
| `CYANPRINT_COORDINATOR`| `-c, --coordinator-endpoint` |

## `cyanprint push`

Push templates, processors, plugins, or groups to the registry.

```bash -c
cyanprint push [OPTIONS] <COMMAND>
```

### Options

| Option                       | Default       | Description           |
| ---------------------------- | ------------- | --------------------- |
| `-t, --token <TOKEN>`        | —             | Authentication token  |
| `-c, --config <CONFIG_PATH>` | `cyan.yaml`   | Path to config file   |
| `-m, --message <MESSAGE>`    | `No description` | Publish message    |

### Environment Variables

| Variable      | Corresponding Flag |
| ------------- | ------------------ |
| `CYAN_TOKEN`  | `-t, --token`      |

### Subcommands

#### `push template`

Push a template to the registry.

```bash -c
cyanprint push --token <TOKEN> template <BLOB_IMAGE> <BLOB_TAG> <TEMPLATE_IMAGE> <TEMPLATE_TAG>
```

#### `push processor`

Push a processor to the registry.

```bash -c
cyanprint push --token <TOKEN> processor <IMAGE> <TAG>
```

#### `push plugin`

Push a plugin to the registry.

```bash
cyanprint push --token <TOKEN> plugin <IMAGE> <TAG>
```

#### `push group`

Push a template group (meta-templates with no Docker artifacts) to the registry.

```bash
cyanprint push --token <TOKEN> group <NAME> <TAG>
```
